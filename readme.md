# Лабораторная работа №3 — Бинарное дерево поиска (Вариант 1)

Курс: «Информатика (организация и поиск данных)», 3 семестр.

Реализация абстрактного типа данных на основе структуры данных «Бинарное дерево поиска» (BST) на языке C++ без использования стандартных контейнеров STL. Проект включает базовые операции, лёгкую балансировку, все виды обходов, функциональные операции (`map`, `where`, `reduce`), сериализацию в различные форматы и операции над поддеревьями.

## Архитектура и логика работы

### 1. DynamicArray (Управление памятью)
Реализован собственный динамический массив, который используется как базовый контейнер (вместо `std::vector`).
Он инкапсулирует ручное управление памятью (`new[]` и `delete[]`), реализует **Rule of Five** (глубокое копирование, move-семантику) и поддерживает удвоение ёмкости (capacity) при переполнении. Внутри дерева он используется для создания стека при итеративных обходах и для временного хранения узлов при балансировке.

### 2. BinaryTree (Ядро структуры)
Класс наследуется от абстрактного интерфейса `IDictionary`. Узлы хранятся в куче и связаны указателями `left` и `right`.

- **Итеративность:** Все операции (вставка, поиск, удаление, обходы, очистка памяти в деструкторе) реализованы итеративно с использованием собственного стека на базе `DynamicArray`. Это исключает риск переполнения системного стека (Stack Overflow) при работе с вырожденными деревьями (глубиной до 10^6 элементов).
- **Удаление:** Используется двойной указатель `Node** link`. При удалении узла с двумя детьми ищется преемник (минимальный элемент в правом поддереве), который встаёт на место удаляемого. Двойной указатель позволяет переписывать связи родителя напрямую без хранения переменной `parent`.
- **Балансировка:** Чтобы дерево не вырождалось в связный список, реализована лёгкая балансировка. Если высота дерева превышает порог `4 * log2(N + 1) + 1`, дерево пересобирается в идеально сбалансированное из середины In-order обхода. Это гарантирует амортизированную сложность операций `O(log N)`.
- **Копирование:** Реализовано глубокое копирование (конструктор и оператор присваивания). Копия сохраняет форму исходного дерева, но создаёт полностью независимые узлы в памяти. Присваивание использует идиому copy-and-swap для гарантии безопасности исключений.
- **Обходы (Visitor и State Machine):** Изначально метод `Traverse` содержал три дублирующихся блока кода (для пре-, ин- и пост-ордера). В ходе рефакторинга архитектура была изменена согласно принципу DRY. Теперь обход реализован через **единый итеративный цикл на основе конечного автомата (State Machine)**.
  Стек хранит не просто указатели на узлы, а структуры `StackFrame` с состоянием узла:
    - `0` — только что вошли в узел;
    - `1` — вернулись из первого ребенка;
    - `2` — вернулись из второго ребенка.
  Форма обхода (скелет алгоритма) теперь едина для всех 6 случаев, а конкретный порядок (КЛП, ЛКП, ЛПК и их зеркальные варианты) задается через передачу двух флагов: `visitState` (на каком шаге вызывать лямбду-посетителя: 0, 1 или 2) и `mirrored` (в каком порядке заталкивать детей в стек).
### 3. TreeOperations (Прикладные задачи)
Все операции вынесены за пределы класса дерева (принцип единственной ответственности) и работают через метод `Traverse`.

- **Функциональные операции:** `Map` создаёт новое дерево, применяя функцию к ключам. `Where` фильтрует узлы по предикату. `Reduce` сворачивает дерево в одно значение (аккумулятор).
- **Сериализация (стандарт):** `ToString` и `FromString` конвертируют дерево в строку вида `1:10|2:20` и обратно. Реализована валидация формата (проверка на наличие двоеточий, дубликатов ключей, битых чисел).
- **Сериализация (по формату):** Функции `ToStringByFormat` и `FromStringByFormat` позволяют задать шаблон вывода, например `{К}(Л)[П]`. Символы К, Л, П заменяются на значения ключей и рекурсивные вызовы поддеревьев. Парсер корректно обрабатывает пустые поддеревья и многобайтовую кодировку (UTF-8).
- **Список пар:** `ToStringParentList` сохраняет дерево в виде связей `родитель->ребенок`. Используется Pre-order обход для вывода всех рёбер.
- **Работа с поддеревьями:** `ExtractSubtree` создаёт глубокую копию ветки, начиная от заданного ключа. `ContainsSubtree` проверяет, содержится ли одно дерево в другом. Для этого сравниваются их Pre-order (КЛП) обходы, так как этот порядок однозначно кодирует структуру дерева.
- **Слияние (`Merge`):** Поэлементно переносит второе дерево в первое. Вызывает исключение при попытке вставить дубликат ключа.

## Известные ограничения

- При сериализации по формату `{К}(Л)[П]` из строки считываются только ключи, значения восстанавливаются по умолчанию (так как стандарт строки формата не задаёт разделителя для значений).
- Балансировка (`Rebalance`) требует выделения временного массива размером N для пересборки дерева, что даёт пиковое потребление памяти `O(N)` в момент перестройки.
